# Security Policy

We take the security of OM1 and its users seriously. If you believe you’ve found a vulnerability, please follow the process below.

## Reporting a Vulnerability

- **Preferred:** Use GitHub’s **Private Vulnerability Reporting** on this repository (Security → “Report a vulnerability”).  
- Alternatively, open a **Security Advisory draft** (Security → Advisories) so we can coordinate a fix and CVE if needed.
- Please include:
  - A clear description of the issue and impact
  - A minimal reproduction (if possible)
  - Affected commit / tag / environment
  - Your contact for follow-up

> Please do **not** open public issues for vulnerabilities until we’ve coordinated a disclosure.

## Supported Versions

OM1 is under active development. We prioritize:
- **`main` branch** (latest)
- **Latest public beta release tags** (e.g., `v1.0.0-beta.x`)

Older tags/commits may not receive security patches.

## Response Targets

We aim to:
- **Acknowledge** your report within **72 hours**
- Provide an **initial assessment** within **7 days**
- Share a **remediation plan/ETA** after triage

Timelines may vary for complex issues; we’ll keep you updated.

## Coordinated Disclosure

Once a fix is available (or a mitigation is documented), we prefer a coordinated disclosure. We’re happy to credit researchers in the release notes unless you prefer to remain anonymous.
