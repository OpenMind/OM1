# Developer Cookbook

The **Developer Cookbook** is a curated collection of practical, high-impact recipes designed to help you extend, customize, and build on top of the OpenMind (OM1) platform. While the Quickstart teaches you how to *use* OM1, this guide focuses on how to **engineer** with it.

### Core Capabilities

With the OM1 framework, you can:

* **Build** bespoke configuration files.
* **Introduce** custom operational modes.
* **Configure** and integrate new input plugins.

1. Complete the [Getting Started](https://www.google.com/search?q=../developing/1_get-started.mdx) guide.
2. Verify that **OM1** is correctly installed in your local environment.

## Development Workflow

To maintain high code quality and system stability, follow these mandatory workflow steps.

### 1. Linting and Quality Control

We use `pre-commit` to automate code formatting and linting. This must be configured before your first contribution.

* **Setup:** Install [pre-commit](https://pre-commit.com/) and run `pre-commit install`.
* **Manual Check:** To audit all files regardless of your commit status, run:
```bash
pre-commit run --all-files

```



### 2. Documentation Updates

If your changes affect the core system, ensure the documentation remains synchronized. We use a sync script for secondary systems like Mintlify:

```bash
# Ensure the script is executable (first time only)
chmod +x scripts/mintlify.sh

# Sync documentation
./scripts/mintlify.sh

```

### 3. Unit Testing

We use `pytest` for our testing suite. Run tests with the following command to see detailed debug logs:

```bash
uv run pytest --log-cli-level=DEBUG -s

```

> 
> **Maintainability Matters:** Always use **type hints** and **docstrings** for new functions. This ensures the codebase remains navigable for the entire community.
